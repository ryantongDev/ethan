## 九、药物风险分层

请建立以下三个风险层。

### 低风险层：药食同源与常见食疗类

包括但不限于：

山药、薏苡仁、茯苓、莲子、芡实、大枣、生姜、陈皮、佛手、砂仁、麦芽、山楂、枸杞、百合、银耳、黑芝麻、桑葚、菊花、薄荷、紫苏、葱白、桂圆、罗汉果、玉竹、黄精、赤小豆、绿豆、扁豆、蜂蜜、梨、萝卜、乌梅。

这些材料可以给出相对明确的日常调理建议，但仍需标注体质不合、过敏、慢病和现用药风险。

### 中风险层：常用中药但需要辨证

包括但不限于：

黄芪、党参、白术、当归、熟地、生地、麦冬、五味子、柴胡、黄芩、黄连、栀子、苍术、厚朴、半夏、干姜、桂枝、麻黄、大黄、芒硝、桃仁、红花、丹参、牛膝。

这些药物可以分析方证、剂量参考、服法和加减方向，但必须强调辨证、炮制、剂量、疗程和现用药冲突。

### 高风险层：有毒、峻烈、强作用药物

包括但不限于：

附子、川乌、草乌、生半夏、生南星、细辛、马钱子、巴豆、甘遂、大戟、芫花、牵牛子、斑蝥、雄黄、朱砂、轻粉、水银类、蟾酥、洋金花、蜈蚣、全蝎、水蛭、虻虫、土鳖虫。

这些药物必须进入高风险模式：

* 明确标注"高风险/有毒/需专业医生判断"；
* 不给唯一结论；
* 不建议用户自行使用；
* 不给可直接执行的剂量和疗程；
* 必须说明炮制、剂量、煎煮、配伍、体质禁忌都会影响安全性；
* 必须提示需要专业中医师或相关专家判断；
* 可以解释经典依据和方证逻辑，但不能给自行执行方案。

## 十四、中断续跑规则

每次启动时，必须先检查：

1. `progress/state.json`
2. `progress/checkpoint.md`
3. `progress/next_actions.md`
4. `progress/completed_files.md`
5. `progress/failed_files.md`

如果发现已有进度，必须从上次中断位置继续，不要重复处理已完成文件。

如果发现 token 溢出、上下文不足或任务中断，应：

1. 保存当前已完成内容；
2. 更新 `state.json`；
3. 更新 `checkpoint.md`；
4. 更新 `next_actions.md`；
5. 将当前任务拆成更小子任务；
6. 下次启动后继续执行。

如果运行环境支持计时或循环监控，请每 5 分钟执行一次自检：

1. 当前是否还在处理任务；

## 十七、质量要求

所有生成文件必须使用中文。

不要编造不存在的经典原文。
如果没有找到依据，就写"当前知识库未检索到直接依据"。

所有方药、剂量、炮制、服法、疗程分析，都必须保留风险提示。

高风险药物必须严格限制。
药食同源材料可以更积极给建议，但仍需说明体质差异和不适反应。

最终知识库应能支持以下用户问题：

1. "我饭后胃胀嗳气，可能适合什么经方？"
2. "半夏泻心汤适合什么证？"
3. "理中汤和小建中汤怎么鉴别？"
4. "我脾胃虚寒，药食同源怎么调理？"
5. "附子在经方中有什么作用，为什么不能自己用？"
6. "请根据我的体质档案，分析候选经方和加减方向。"
7. "请引用《伤寒论》《金匮要略》和胡希恕观点说明依据。"

## 十九、额外调度指令

每 5 分钟检查一次 `tcm-agent/progress/state.json`。如果 status 不是 completed，或 build_log.md 超过 5 分钟没有更新，就用同一个 prompt 重新启动 Agent，并要求它先读取 `progress/next_actions.md` 后续跑。

这个 prompt 的设计重点是：**第一次就能跑起来，中断也不怕，后面能一点点把全文库升级成可用于经方适配分析的结构化知识库。**
